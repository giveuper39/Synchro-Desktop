# Пауза и продолжение

До версии 0.2.2 Play после любой паузы делал полный `takeover`, закрывал
LibVLC Media и заново открывал HTTP-поток, декодер и буфер. На быстром Wi-Fi
это всё равно создавало ощутимую задержку.

Теперь обычный Play сразу продолжает уже открытый буфер. Упорядоченный
`POST /api/resume` проверяет состояние ПК в фоне после завершения предыдущей
передачи паузы. Сервер заново читает файл, позицию, дорожки, задержку,
скорость и очередь; только при совпадении возвращает `resumeInPlace=true`.
Каждое подтверждение получает новый session ID, поэтому старые пакеты не
могут изменить новый сеанс. Позиция продолжающегося телефона не откатывается
к точке предыдущей паузы.

Если на ПК изменили просмотр, телефон принимает его актуальное состояние.
До ответа может коротко продолжаться прежний буфер. Пауза, повторный Play,
уход с экрана и пауза во время смены серии сохраняют последнее действие
пользователя; отложенное подтверждение не запускает видео обратно.
При сетевой ошибке телефон останавливается и показывает ошибку подключения.

Пауза на телефоне выполняется локально; подтверждение применения настроек
на ПК приходит отдельно. Windows-адаптер больше не ждёт по 300 мс на каждом
повторном Pause для уже остановленного файла. Проверка стабильной паузы при
открытии другой серии и проверки точной позиции/дорожек сохранены.

Это ускоряет обычное продолжение. Первое открытие файла, переход на другую
серию, смена аудиовыхода и пересоздание декодера требуют подготовки потока.

## Проверка

47 тестов Python и 8 Android unit-тестов дополняются нативным прогоном
`PlaybackLatencyInstrumentation`. Он проверяет быстрые Play/Pause, смену
серии и позиции на ПК и поздний ответ, приходящий после новой паузы.

Для воспроизведения используйте `tools/latency_fixture.py` с двумя
сгенерированными MKV по 3 минуты, `--media-dir`, `--data-dir` внутри `.data`
и отдельным `--token`. Фикстура не обращается к PotPlayer. По умолчанию она
слушает loopback:18765; `adb reverse tcp:18765 tcp:18765` делает её доступной
выделенному эмулятору. Соберите `:app:assembleDebugAndroidTest`, установите
основной APK и тестовый APK с `adb install -t`, затем выполните:

```text
adb shell am instrument -w -e server http://127.0.0.1:18765 -e token <test-key> dev.potplayer.handoff.test/dev.potplayer.handoff.PlaybackLatencyInstrumentation
```

Фикстура специально задерживает чтение ПК на 650 мс, а возврат паузы на
800 мс. Тесты не должны запускаться с реальным ключом или рабочим сервером;
runner принимает только порт 18765.
