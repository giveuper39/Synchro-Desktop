# Потоковое видео и PotPlayer

Просмотр локального видео на Android с продолжением из PotPlayer и возвратом
на ту же серию и позицию. Компьютер передает **сам исходный файл по HTTP**;
видео и звук воспроизводит LibVLC на телефоне. Окно PotPlayer при этом на паузе.

Это независимый сервис и Android-приложение. В проект не входят PotPlayer,
его DLL, декомпилированный код, личные медиаданные или ключи подключения.

## Как пользоваться

1. На Windows установите Python 3.11+ и FFmpeg, чтобы `python`, `ffprobe` и
   `ffmpeg` находились в PATH. `ffprobe` нужен для метаданных дорожек.
   Скрипт запуска создаёт локальную `.venv` и устанавливает небольшой пакет
   `qrcode` для QR-кодов; последующая работа происходит в локальной сети.
2. Откройте локальное видео в одном экземпляре PotPlayer.
3. Запустите `start-server.cmd`. Откроется локальная страница подключения.
4. Если приложение ещё не установлено, выберите на ПК вкладку
   **«Установить приложение»** и сканируйте код обычной камерой телефона.
   Либо откройте показанный адрес компьютера и скачайте `/receiver.apk`.
   Для этого положите
   собранный APK в `dist/potplayer-receiver.apk` (готовая локальная сборка
   поставляется отдельно от исходников).
5. Откройте **PotPlayerReceiver → «Сканировать QR-код»**. Код из вкладки
   **«Подключить телефон»** заполнит адрес, ключ и имя ПК автоматически.
   Подключение сохраняется на телефоне. Нажмите
   **«Продолжить с ПК»**: PotPlayer остановится, а ресивер откроет файл с его
   позиции и настроит озвучку и субтитры.
6. Нажмите кнопку паузы в полноэкранном плеере. Сервис выставит в PotPlayer текущий
   файл, позицию, озвучку, видимость/дорожку субтитров и их задержку. После
   подтверждения можно нажать Play на компьютере.

Видео открывается в альбомном режиме на весь экран. Касание показывает или
скрывает полупрозрачные элементы управления; при просмотре они скрываются
автоматически. Двойное касание слева/справа перематывает на 10 секунд.
Кнопка поворота возвращает портретный режим. Озвучка, субтитры, их задержка,
скорость доступны в нижних панелях Material. Громкость меняется штатными кнопками телефона через системную панель Android.

При обновлении установите APK поверх предыдущего и **перезапустите старое
окно сервера через `start-server.cmd`**. Это применит новую QR-страницу и
обработку обычных разрывов HTTP при паузе/перемотке (WinError 10053/10054).

Громкость телефона и компьютера независимы. Настройки кадра, растяжение и
видеофильтры не переносятся. Скорость поддерживается, когда ее IPC-команды
доступны в установленной версии PotPlayer; старые версии начинают Android
сеанс с 1× и не меняют скорость ПК.

Если вручную запустить PotPlayer, пока телефон еще смотрит видео, компьютер
получает приоритет, а прежний сеанс телефона отзывается. Для обычного возврата
сначала используйте паузу в ресивере — она переносит актуальную позицию.

## Плейлисты

Обычные DPL, M3U и M3U8 сохраняют порядок и повторяющиеся элементы:

```powershell
.\start-server.cmd --playlist "D:\Video\season.dpl"
```

Без `--playlist` сервис читает настройку последнего сохраненного альбома
PotPlayer. **Несохраненную живую очередь сервис не извлекает.** Если альбом
работает как навигация папки, ресивер получает медиафайлы этой папки с
естественной сортировкой по имени и показывает соответствующее предупреждение.
История просмотра не используется как очередь.

Чтобы передать произвольную текущую очередь точно, сначала сохраните ее в
PotPlayer через «Сохранить список как…» (F2 в окне плейлиста), затем передайте
этот DPL сервису. Сетевые URL в плейлистах пока не поддерживаются.

## Сборка Android

См. [android/README.md](android/README.md). Используется Java, Android Gradle
Plugin и LibVLC 3.7.7. Получаются отдельные APK для arm64-v8a, x86_64 и
универсальный APK. Скрипт подготовки инструментов хранит SDK/Gradle локально
в игнорируемой `.tools`; глобальные настройки среды не требуются.

Удобный запуск сервера из исходников:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e server
.\.venv\Scripts\python.exe -m potbridge --open
```

Параметры `--player-exe`, `--player-pid`, `--bind`, `--port` и
`--advertise-host` позволяют выбрать экземпляр плеера и LAN-интерфейс.
Последний параметр полезен, если VPN перехватывает маршрут по умолчанию.
Входящие подключения Python должны быть разрешены в частной сети Windows.

## Устройство проекта

| Модуль | Ответственность |
| --- | --- |
| `server/potbridge/player.py` | Сериализованный адаптер PotPlayer |
| `win32.py`, `menus.py`, `track_menus.py` | IPC, дорожки, задержка, точная перемотка |
| `playlist.py`, `library.py` | Очередь, разрешенные файлы и метаданные |
| `sessions.py` | Владение просмотром, порядок событий, возврат и отключение |
| `http_server.py` | Авторизация, JSON API, HTTP Range и передача файла |
| `pairing.py` | Локальные QR-коды подключения и установки APK |
| `android/.../ApiClient.java` | HTTP без автоматических перенаправлений |
| `PlaybackController.java` | LibVLC, очередь, дорожки и задержка |
| `MainActivity.java` | Координация подключения и передачи состояния |
| `ReceiverUi.java`, XML | Отдельное меню подключения и полноэкранное управление |
| `PlayerSheets.java` | Панели настроек Material |
| `PairingCode.java`, `QrScannerActivity.java` | Проверка QR-ссылки и камера |

`sessionId` меняется при новом захвате просмотра. Каждое сообщение Android
имеет возрастающий `sequence`; повторы и запоздалые события не откатывают
прогресс. Во время воспроизведения Android отправляет позицию каждые две
секунды. Явная пауза отправляется с повторами и подтверждается после применения
состояния на ПК. Буферизация не считается пользовательской паузой.

После 15 секунд без сообщений сервис сохраняет последнюю полученную позицию
в остановленный PotPlayer и отзывает сеанс. Потребуется новое подключение.
Контрольное состояние также записывается в `.data/last-session.json`; после
перезапуска сервера оно не применяется автоматически к уже открытому фильму.

Видео отдается только по непрозрачным ID из разрешенной очереди, с ключом
подключения в URL медиаресурса. JSON API использует Bearer-ключ. Журнал
HTTP-запросов выключен, чтобы URL с ключом не попадали в логи. Это протокол
для доверенной локальной сети; TLS в самом сервисе пока не реализован.

## Совместимость и границы прототипа

- Адаптер проверен на Windows x64 / PotPlayer 1.7.22318, русское меню.
  Предусмотрены английские имена основных меню; другие версии и локализации
  требуют проверки. Передавайте `--player-pid`, если открыто несколько копий.
- Дорожки читаются из обновленных галочек меню. Задержка читается и задается
  через штатный диалог. Он и меню кратко появляются при передаче просмотра.
  Открытые пользователем диалоги сервис не закрывает: нужно закрыть их и повторить.
- Для точной перемотки режим прыжка по ключевым кадрам временно выключается
  и восстанавливается после подтвержденного перехода.
- Перенос встроенных аудиодорожек и субтитров проверяется по их порядку и
  метаданным. Неоднозначные названия, нестандартные splitters и внешние
  SRT/ASS-файлы пока требуют доработки; автоматически внешние файлы не отдаются.
- Файл передается без перекодирования. Возможность декодирования и скорость
  зависят от LibVLC, устройства и локальной сети.
- APK пока подписаны отладочным ключом. Для публикации релиза нужен свой
  постоянный ключ подписи; ключи не должны попадать в Git.
- У новой сборки проверены выравнивание ELF LOAD и ZIP для 16 КБ. Полная
  работа на устройстве с размером страницы 16 КБ не подтверждена: отдельная
  строгая проверка GNU_RELRO у библиотек пока не проходит. Детали и
  воспроизводимая проверка находятся в Android-документации.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют настоящий HTTP-сервер, диапазоны байтов и авторизацию,
парсинг очередей, повторы/перестановку событий, разрыв сети и приоритет ПК.
Android имеет отдельные протокольные unit-тесты и lint-проверку.

`tools/verify_native.py --exercise` намеренно меняет позицию, дорожки и
задержку в **открытом остановленном** PotPlayer, затем восстанавливает
исходное состояние в `finally`. `tools/verify_stream.py` проверяет передачу
реального файла и его видео/аудиодекодирование по HTTP. Эти интеграционные
проверки запускаются отдельно; результаты с личными путями сохраняются
только в игнорируемой `.data`.
