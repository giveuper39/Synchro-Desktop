# Проверка Synchro 0.4.0

## Автоматические проверки

- 157 Python unit/integration тестов: владение просмотром, HTTP Range и обрывы, QR/mDNS, OTA, адаптеры Windows/VLC/mpv, источник YouTube, бинарный фотобуфер и запрет второго сервера.
- 12 Node-тестов: расширение Chrome, настоящие скрипты коннектора страницы и Android YouTube embed.
- Android JVM-тесты, debug/release сборки и lint без ошибок. Предупреждения зависимостей/ресурсов остаются.
- APK: один постоянный release-сертификат; подпись, ABI, лицензии, ZIP и ELF PT_LOAD alignment 16 КБ проверяются скриптом. GNU_RELRO остаётся ограничением LibVLC.

## Нативные сценарии

На выделенном Android 14 эмуляторе, собственных видео и loopback-сервере:

- Выбор источника Windows, реальное декодирование файла, скрытые неподдерживаемые дорожки, HTTP 409 при смене источника во время просмотра на телефоне.
- Тёплый Play после паузы — 24 мс в контрольном прогоне; быстрая повторная пауза и обновлённая серия/позиция на ПК применяются корректно. Это измерение данного теста, а не гарантия задержки любого устройства/сети.
- Home переводит локальное видео в PiP, системные Pause/Play работают, обмен доступен под мини-плеером, закрытие отправляет позицию на ПК.
- Фото: настоящий Android content URI → shell-мост → адаптер Windows в памяти; обратно — staging → фоновый receiver → системный буфер эмулятора. Проверены PNG/JPEG/EXIF, границы размеров, независимое чтение URI, отсутствие эха и накопления staging-файлов. Реальный Windows/OnePlus буфер не менялся тестами.
- Ручной текст и вкладки, очистка отправленного поля, открытие входящей ссылки в браузере.

На Windows использованы настоящие Windows Media Player, VLC и mpv с синтетическими файлами. Проверены пауза, seek, возврат серии и HTTP 206 с точными байтами исходного файла. PotPlayer handoff проверялся в предыдущих версиях на физическом OnePlus; его API сохраняется.

## Границы доказательств

YouTube: проверены протокол, origin/nonce/window guards, управление выбранной страницей и Android embed-скрипт. Доступ к живому YouTube на среде разработки завершался `ERR_SSL_PROTOCOL_ERROR`. Полный просмотр реального ролика на физическом телефоне ещё требует полевого теста; проверки TLS не ослаблялись.

Автоматический текстовый мост ранее запускался на OnePlus с Android 16. Фотобуфер 0.4.0 проверен на Android 14 эмуляторе; отдельный физический прогон Android 16 ещё не выполнен. Пользователь устанавливает новую версию обычным OTA-потоком.

QR использует стандартный Android ADB-формат. Обычный QR проверен физическим телефоном; первое системное QR-сопряжение нового телефона остаётся отдельным полевым сценарием.

Windows OTA проверен живым переходом 0.3.1 → 0.4.0 через штатный экран обновлений: загрузка совместимого ZIP, замена программных файлов, запуск 0.4.0, сохранённые ключ подключения и настройки буфера. Конфигурация после обновления указывает на новые репозитории Synchro. Откат при намеренной ошибке запуска проверялся ранее. Все четыре канала (два основных и два миграционных) отдают проверяемый стабильный релиз 0.4.0.

Android проверил получение опубликованного релиза настоящим экраном обновлений. SHA-256 и совпадение release-сертификата 0.3.0/0.4.0 подтверждены отдельно. Полный сценарий скачивания и подтверждения установки в системном UI эмулятора не завершён: автоматическая проверка отклонила ADB-сценарий без пояснения причины.

Скриншоты в README сняты с настоящего интерфейса 0.4.0. Медиа и данные подключения в них демонстрационные.

## Дополнения 0.4.1

162 Python-проверки и 20 Node-проверок проходят. Добавлены единый QR с секретом только во фрагменте, публичная страница установки и приватный endpoint генерации, mDNS-идентификаторы ADB с пробелами, исчезновение телефона и сохранение ошибки установки при следующем опросе.

Настоящий ZXing декодирует матрицу нового QR, после чего JVM-парсер извлекает подключение. На Android-эмуляторе проверены запуск Activity с HTTP-ссылкой из QR и разрешение браузерного Android Intent в установленное приложение. Фоновая отладка для основного QR не требуется. Автоматический переход из произвольной камеры/браузера без дополнительного нажатия не гарантируется Android.
